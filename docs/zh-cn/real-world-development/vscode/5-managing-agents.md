在智能体模式下，GitHub Copilot 会自主探索代码库、提出更改、编辑文件并运行命令。由于这些工作会实时在你的计算机上进行，VS Code 中的 Copilot Chat 会持续显示每次工具调用和文件编辑。你可以内联审查每个差异、接受或拒绝单项更改，并通过后续提示引导对话，不必离开编辑器即可完善或扩展工作。

在本练习中，你将：

- 实时监控无障碍访问智能体的工作。
- 审查并接受建议的文件编辑。
- 在会话进行中引导智能体，在高对比度模式之外添加浅色模式切换。

## 场景

你在[练习 4][previous-lesson]中使用的无障碍访问自定义智能体正在实现高对比度模式。工作进行期间，设计团队又提出一项需求：他们还希望为觉得默认主题太暗的用户添加浅色模式切换。无需重新开始对话，你可以引导现有会话扩展工作。

## 监控 Copilot 的进度

Copilot Chat 视图会显示智能体执行的每个步骤，包括探索的文件、运行的命令和提出的编辑。每项文件编辑都会以内联差异显示，并提供 **Keep** 和 **Undo** 控件。

1. 返回练习 4 中的 Copilot Chat 视图。
2. 智能体工作时滚动聊天记录，查看每次工具调用。你会看到文件读取、文件编辑和它请求运行的终端命令。
3. 智能体提出文件编辑时，差异会以内联形式显示：
   - 选择 **Keep** 接受更改。
   - 选择 **Undo** 撤销更改，让智能体再次尝试。
4. 也可以打开聊天顶部的 **Files changed** 指示器，查看智能体在此会话中修改的全部文件。

> [!NOTE]
> 如果工具调用请求权限（例如运行终端命令），智能体会暂停并显示 **Allow** 提示。只批准你认可的命令。

5. 等待智能体完成高对比度模式实现。完成后应显示更改摘要。

## 引导智能体添加浅色模式

高对比度模式已完成，现在在同一对话中添加浅色模式切换。继续当前会话，智能体会保留之前工作的上下文，包括已修改组件、采用的样式方式和本地存储模式。

1. 在 Copilot Chat 输入框中发送以下后续提示：

   ```plaintext
   做得不错！现在在高对比度切换旁添加浅色模式切换。浅色模式应遵循相同模式：使用本地存储保留设置，并在用户界面 (UI) 的同一区域提供入口。用户应能独立启用高对比度和浅色模式。
   ```

2. 智能体会检查已有更改，并提出添加浅色模式的修改。
3. 像审查高对比度模式一样审查每项新编辑，使用 **Keep** 或 **Undo** 处理每个差异。
4. 如果智能体的实现方向不符合预期（例如尝试以不喜欢的方式重构切换 UI），可以选择聊天输入框旁的 **Stop** 按钮停止它，然后发送澄清说明。

> [!TIP]
> 引导正在运行的会话比从头开始更快。可以使用后续提示调整方向，例如“简化 CSS，使用 CSS 变量而不是重复选择器”；也可以纠正方向，例如“不要添加第三个开关，将浅色模式集成到现有设置面板”；或扩展范围，例如“同时为两个开关添加键盘快捷键”。

## 审查工作集

提交更改前，快速审查智能体修改的所有内容。

1. 在 VS Code 中打开 **Source Control** 视图。
2. 审查已更改文件的完整列表。应能看到 Astro 组件、样式和相关测试的更新。
3. 打开几个更改过的文件并查看差异。确认实现体现了自定义智能体中的无障碍模式，包括可访问的富互联网应用程序 (ARIA) 属性、键盘导航、语义化超文本标记语言 (HTML) 和本地存储持久化。
4. 确认满意后，在 Source Control 面板中暂存并提交更改。下一课会发布这些更改。

## 总结和后续步骤

你已使用 Copilot Chat 智能体模式监控并引导正在进行的会话：实时审查文件编辑、接受或拒绝更改，并通过后续提示扩展工作，同时保留上下文。

在本课中，你：

- 实时监控了智能体的工作。
- 接受或拒绝了单项文件编辑。
- 使用后续提示引导正在运行的会话。
