Copilot をエージェントモードで使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行を自律的に行います。VS Code の Copilot Chat では、ローカル環境での作業中にツールの呼び出しやファイルの編集を確認できます。各差分をインラインでレビューし、変更を個別に承認または元に戻し、エディターを離れずに追加のプロンプトを送って作業を調整、拡張できます。

この演習では、次の作業を行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして承認します。
- セッションの途中でエージェントに指示し、ハイコントラストとともにライト モードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用カスタムエージェントが、ハイコントラスト モードを実装しています。作業中にデザイン チームから、既定のテーマが暗すぎると感じるユーザー向けにライト モードの切り替えも追加したいと依頼されました。新しい会話を始めるのではなく、既存のセッションに指示を追加して作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが確認するファイル、実行するコマンド、提案する編集が順に表示されます。ファイル編集は差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. 演習 4 から Copilot Chat ビューに戻ります。
2. 作業中にチャットをスクロールし、ツールの呼び出しを確認します。ファイルの読み込み、編集、実行を求めるターミナル コマンドが表示されます。
3. エージェントがファイル編集を提案したら、差分を確認します。
   - **Keep** を選択すると変更を承認します。
   - **Undo** を選択すると変更を元に戻し、エージェントに再検討させます。
4. チャット上部の **Files changed** インジケーターを開くと、このセッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ツールの呼び出しで許可 (例: ターミナル コマンドの実行) が必要な場合、エージェントは一時停止して **Allow** を表示します。実行を許可するコマンドを確認してから承認してください。

5. エージェントがハイコントラスト モードの実装を完了するまで待ちます。変更内容をまとめた最終メッセージが表示されます。

## ライト モードを追加するようエージェントに指示する

ハイコントラスト モードが実装されたら、同じ会話を使ってライト モードの切り替えを追加します。同じチャット セッションを続けるため、エージェントは前の作業で扱ったコンポーネント、スタイルの方法、local storage の利用方法を含むコンテキストを維持します。

1. Copilot Chat の入力欄に、次のフォローアップ プロンプトを送信します。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントが既存の変更を調べ、ライト モードの追加を提案する様子を確認します。
3. ハイコントラスト モードの場合と同様に、編集ごとに差分を確認し、**Keep** または **Undo** を選択します。
4. 望まない方向に進んだ場合 (例: トグル UI の意図しないリファクタリング) は、チャット入力欄の横にある **Stop** ボタンで停止し、次のメッセージで意図を伝えます。

> [!TIP]
> 作業中のセッションに追加指示を送ると、最初からやり直すより速く調整できます。フォローアップ プロンプトで、変更 (「CSS を簡潔にし、セレクターの重複ではなく CSS 変数を使ってください」)、軌道修正 (「トグルを 3 つにせず、ライト モードを既存の設定パネルに追加してください」)、範囲の拡張 (「両方の切り替えにキーボード ショートカットも追加してください」) を依頼できます。

## 作業セットをレビューする

変更をコミットする前に、エージェントが編集した内容全体を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されているはずです。
3. 変更されたファイルをいくつか開いて差分を確認します。カスタムエージェントの指針に沿った Accessible Rich Internet Applications (ARIA) 属性、キーボード ナビゲーション、セマンティック HTML、local storage による設定の保存が実装されていることを確認します。
4. 問題がなければ、Source Control パネルで変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードで、進行中のセッションを監視し、指示しました。ファイル編集の差分を確認して承認または却下し、コンテキストを維持したままフォローアップ プロンプトで作業を拡張しました。

このレッスンでは、次の作業を行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個別のファイル編集を承認、却下しました。
- フォローアップ プロンプトでセッションの途中から指示しました。

[次のレッスン][next-lesson]では、アクセシビリティの作業をプルリクエストとして公開し、このワークショップでローカルのカスタムエージェントが行った変更をレビューします。
